# 后端文档地图

## 入口

| 入口 | 用途 | 何时读取 |
| --- | --- | --- |
| `AGENTS.md` | Agent 工作方式、最小必读集与按需加载规则 | 每次任务开始 |
| `docs/harness/README.md` | Harness 交付流程与入口索引 | 每次后端开发任务开始 |
| `docs/harness/工程规则唯一事实源.md` | 强制工程约束 | 每次后端开发任务开始 |
| `docs/harness/后端文档规范.md` | 文档分类、事实源和维护责任 | 文档相关任务或新增文档类型时 |
| `docs/guide/业务模块目录规范.md` | 业务模块目录职责与新增 package 登记规则 | 新增/扩展业务模块或新增 package 时 |
| `docs/base/项目业务module导航.md` | 模块职责与代码落位 | 涉及模块选择、扩展或定位时 |
| `docs/kn/总目录.md` | 按业务/功能定位 API 聚合 | 涉及页面、接口或业务能力时 |

## 按任务加载

| 任务 | 必读 | 按需补读 | 交付时回写 |
| --- | --- | --- | --- |
| 小范围代码修复 | 工程规则、目标代码、相关测试 | 相关 API 原子文档 | 测试或交付记录（如需要） |
| 新增/扩展业务模块 | 工程规则、模块地图、DDD 指南、业务模块目录规范、功能输入模板 | `docs/modules/<domain>/`、相关业务通用文档、SQL 设计 | 模块地图、模块文档、目录规范、迁移/API/交付记录 |
| 列表/表单/保存 | DDD 指南、目标模块、相关 API 原子文档 | 通用列表或字段能力文档、业务聚合 | API、聚合导航、业务个性化文档 |
| HTTP 契约变化 | 前后端契约规范、受影响 API 原子文档、Controller/DTO/VO | 前端仓库对应调用点、业务/功能聚合 | API 原子、`docs/kn` 聚合、总目录 |
| 数据库结构变化 | 数据库迁移规范、Flyway 基线记录、目标模块 | 可读 SQL 设计、领域规则 | Flyway、`docs/sql/`、模块/API 文档 |
| 跨模块公共能力 | 工程规则、DDD 指南、已有通用能力文档 | 所有调用模块、API/数据契约 | `docs/guide/common/`、调用模块文档、地图 |
| 业务规则或状态机 | 目标模块文档与领域代码 | `docs/guide/business/`、历史设计 | 模块个性化文档或业务通用文档 |
| 独立功能交付 | 功能交付输入模板、目标模块和验收标准 | `docs/features/<feature>/`、ADR、API/数据文档 | 功能文档、稳定事实源、交付记录 |
| 架构决策 | 工程规则、现有 ADR、受影响代码 | 历史方案和外部约束 | `docs/adr/`、工程规则或指南 |
| 追溯历史方案 | 当前事实源 | `docs/superpowers/specs/`、`plans/` | 不因追溯重写当前规则 |

## 当前存量映射

| 现有位置 | 当前职责 | 后续策略 |
| --- | --- | --- |
| `docs/harness/` | 工程规则、交付流程、迁移、契约、验证与发布 | 继续作为 Harness 唯一入口 |
| `docs/base/` | 项目/模块职责导航 | 新模块或职责变化时增量更新 |
| `docs/guide/` | DDD 与跨模块实现指南 | 新增稳定通用能力时按能力建子目录 |
| `docs/kn/` | 业务聚合、功能聚合、双入口导航 | 保持摘要和链接，不放完整接口正文 |
| `docs/api/endpoints/` | 单接口完整契约 | 所有新增或变更接口在此维护 |
| `docs/api/` | 存量接口聚合或历史文档 | 不批量迁移；触及内容时逐步拆为原子文档 |
| `docs/sql/` | 人可读的数据设计说明 | 与 Flyway 同步，非执行事实源 |
| `docs/superpowers/` | 存量方案、计划和报告 | 只作追溯，不作为现行规则入口 |

## 创建与检索规则

- 新建文档前，先在本地图按任务确定类别；已有完整事实源时只补链接或摘要。
- 新建模块特有文档时，创建 `docs/modules/<domain>/README.md`，并在模块地图中登记责任边界。
- 新建可复用能力时，创建 `docs/guide/common/<capability>/README.md`；确认至少两个模块可复用后再提升为通用能力。
- 新建独立功能时，创建 `docs/features/<feature>/README.md`；若形成长期架构取舍，再新增 ADR。
- 文档链接优先使用仓库相对路径；地图、聚合和 `AGENTS.md` 只保存稳定入口，避免列举瞬态方案或实施记录。
