# 资金往来业务设计

## 适用范围

本文定义结算模块中的客户收款与供应商付款镜像模型，覆盖销售发票、应收款、收款单、预收款及预收核销，以及采购发票、应付款、付款单、预付款及预付核销。

本文是资金往来业务语义、镜像关系和数据设计的事实来源。已实现的收款、应收与收款核销结构以以下 Flyway 迁移和结算模块代码为准：

- `V16__create_receipt_table.sql`
- `V18__create_receipt_payment_table.sql`
- `V20__create_receivable_table.sql`
- `V21__create_sales_invoice_tables.sql`
- `V22__create_receipt_writeoff_table.sql`
- `V29__extend_receipt_writeoff.sql`
- `xbb-erp-module-settlement` 中的 `ReceiptWriteOffService`

新增付款、应付和采购发票的可执行结构以实施时新增的 Flyway 迁移为准；本文与 `docs/sql/资金往来业务表.sql` 提供的 DDL 用于设计评审和迁移编写。

## 目标与边界

### 目标

- 保持收款侧的已实现业务规则，付款侧严格采用对称的领域模型和核销行为。
- 以采购发票确认供应商应付款，以付款单记录实际支付，以预付款余额核销后续应付款。
- 支持一笔预付款核销多笔应付款，也支持一笔应付款由多笔预付款或付款单分次结清。
- 收款、付款通过各自业务单据录入；资金流水统一汇总已生效的收付款明细。
- 让采购发票已付、未付、预付款余额、应付款余额和采购订单开票进度具备一致口径。

### 非目标

- 本期不实现费用报销、员工借款、银行直连、支付回单导入、自动对账、总账凭证或跨币种折算。
- 本期不改造既有 `receipt`、`receipt_payment`、`receivable` 与 `receipt_writeoff` 的表名、字段名和 HTTP 契约。
- 本期不把采购订单本身直接作为应付款；应付款的正式来源是已过账采购发票。
- 本期不将核销明细作为资金流水，也不允许用资金流水替代采购发票或应付款。

## 统一术语与镜像关系

| 收款侧 | 付款侧 | 含义 |
| --- | --- | --- |
| 销售发票 `sales_invoice` | 采购发票 `purchase_invoice` | 确认对客户债权或对供应商债务的业务发票 |
| 应收开放项 `receivable` | 应付开放项 `payable` | 用于余额、账龄和核销的财务开放项 |
| 收款单 `receipt` | 付款单 `payment` | 企业实际收到或支付款项的业务单据 |
| 预收款 | 预付款 | 尚未分配给应收或应付款开放项的收款/付款余额 |
| 收款明细 `receipt_payment` | 付款明细 `payment_detail` | 按资金账户、支付方式和交易号拆分的实际收付记录 |
| 预收核销 `receipt_writeoff` | 预付核销 `payment_writeoff` | 收款/付款余额与应收/应付款余额的分配记录 |
| 客户 `customer` | 供应商 `supplier` | 核销双方必须属于同一往来对象 |
| 收入资金流水 `IN` | 支出资金流水 `OUT` | 对资金账户产生的实际变动 |

术语约束：

- **预收款不是另一张独立单据。**客户收款单的 `remaining_amount` 大于零时，其未核销余额可用作预收。
- **预付款不是另一张独立单据。**供应商付款单的 `remaining_amount` 大于零时，其未核销余额可用作预付。
- **预收/预付核销不是新的资金收付。**它只重新分配已经发生的收款或付款余额，不能重复生成资金流水。
- **采购发票不是供应商实际收款。**采购发票确认企业对供应商的应付款；实际支付由付款单记录。

## 领域关系

```text
销售订单 ──> 销售出库 ──> 销售发票 ──> 应收款
                                           ▲
客户收款（含预收） ──> 预收核销 ────────────┘

采购订单 ──> 采购入库 ──> 采购发票 ──> 应付款
                                           ▲
供应商付款（含预付） ──> 预付核销 ──────────┘

收款明细 receipt_payment ─┐
                            ├──> 资金流水 fund_transaction <── 付款明细 payment_detail
付款明细 payment_detail ───┘
                            │
                      资金账户 fund_account
```

销售发票过账后创建一笔应收款；采购发票过账后创建一笔应付款。应收或应付都不是由用户重复录入的发票副本，而是资金分配、余额和账龄的开放项。

## 已实现收款业务基线

当前收款侧已实现以下稳定行为，付款侧必须镜像：

| 能力 | 当前实现 | 付款侧要求 |
| --- | --- | --- |
| 发票来源 | 已过账销售发票创建应收款 | 已过账采购发票创建应付款 |
| 预收/预付 | `receipt_type=ADVANCE_PAYMENT` 的剩余收款可核销应收 | `payment_type=ADVANCE_PAYMENT` 的剩余付款可核销应付 |
| 余额 | 主表保存 `amount`、`written_off_amount`、`remaining_amount` | `payment`、`payable` 使用完全相同的余额字段 |
| 核销关系 | `receipt_writeoff(receipt_id, receivable_id)` | `payment_writeoff(payment_id, payable_id)` |
| 核销批次 | `writeoff_no` 由业务编号生成 | 使用独立 `PAYMENT_WRITEOFF` 业务编号 |
| 核销校验 | 金额大于零、同客户、双方余额充足 | 金额大于零、同供应商、双方余额充足 |
| 余额状态 | 未核销、部分核销、已核销 | 使用与收款侧相同状态值和计算规则 |

现有 `ReceiptWriteOffService` 明确限制只有 `ADVANCE_PAYMENT` 类型的收款才可通过核销明细核销。因此付款第一期也采用相同规则：只有 `ADVANCE_PAYMENT` 类型付款可执行预付核销。普通供应商付款若需自动或手动关联应付款，应另行定义“付款即核销”的交付语义，不能在本次镜像设计中悄然改变收款侧规则。

## 核心对象与职责

| 对象 | 职责 | 关键金额或关系 |
| --- | --- | --- |
| `purchase_invoice` | 采购发票表头，固化供应商、日期、税额、总额、账期、审核及过账状态 | 含税总额 `amount` |
| `purchase_invoice_line` | 采购发票行，固化商品、数量、单价、税率与金额快照 | 行含税金额 `amount` |
| `purchase_invoice_line_source` | 记录发票行对采购订单行或采购入库行的开票占用 | 来源行、本次数量和金额 |
| `purchase_invoice_business_ref` | 记录采购发票对采购订单、采购入库等表头业务归属 | 可选归属金额 |
| `payable` | 采购发票过账创建的应付开放项，也可容纳期初或手工调整 | 初始、已核销、未核销金额 |
| `payment` | 供应商实际付款，统一承载普通付款、预付款和期初付款 | 实付、已核销、未核销金额 |
| `payment_detail` | 付款按资金账户、方式、交易号拆分的明细 | 每行实际付款金额和手续费 |
| `payment_writeoff` | 一笔预付款对一笔应付款的核销明细 | 核销批次、日期与金额 |
| `fund_transaction` | 已生效收付款明细造成的资金账户变动 | 方向、账户、来源单据、金额 |

## 采购发票与应付款

### 一对一生成规则

正常采购发票遵循与销售发票—应收相同的规则：一张已过账采购发票最多创建一笔应付款；一笔来源为采购发票的应付款只对应一张采购发票。

```text
purchase_invoice.id = payable.source_invoice_id
UNIQUE (corpid, source_invoice_id)
```

期初应付和手工调账不来源于采购发票，分别使用 `OPENING_BALANCE`、`MANUAL_ADJUSTMENT` 标识 `source_type`，并允许 `source_invoice_id` 为空。

### 发票来源与占用

采购发票不在表头强制保存单一 `purchase_order_id` 或 `purchase_inbound_id`，因为一张采购发票可以覆盖多个订单和多张入库单，且同一入库可分次开票。关系由两类表表达：

- `purchase_invoice_line_source`：发票行对采购订单行或采购入库行的精确数量和金额占用。
- `purchase_invoice_business_ref`：发票表头对采购订单、采购入库等业务对象的归属。

默认商品采购场景优先选择已审核采购入库明细开票；服务采购或不需入库场景允许选择已审核采购订单明细。第一期不支持无业务来源的手工采购发票，采购发票必须关联已审核采购入库明细或采购订单明细。

```text
采购来源行可开票数量 = 来源确认数量 - 有效采购发票累计占用数量
采购来源行可开票金额 = 来源确认金额 - 有效采购发票累计占用金额
```

草稿、已作废采购发票不占用最终可开票额度；已过账采购发票占用额度。采购发票红冲或作废必须释放原占用并同步冲减或关闭对应应付款，不允许直接修改已过账发票金额。

### 采购发票过账

```text
审核采购订单
  -> 审核采购入库
  -> 选择可开票入库/订单明细，生成采购发票草稿
  -> 审核并过账采购发票
  -> 在同一事务内创建应付款开放项并固化来源占用
  -> 付款或使用预付款核销应付款
```

采购发票过账时必须校验：供应商与来源单据一致、发票金额未超过可开票余额、表头未税金额/税额/含税金额等于有效发票行汇总金额。一旦过账，不得原地修改供应商、金额、税率、来源占用和到期日；更正通过采购红字发票或受控冲销处理。

## 付款、预付款与付款核销

### 付款单与预付款

付款单记录企业实际向供应商支付的款项。付款发生时如果尚未有匹配应付款，或者付款单的 `remaining_amount` 仍大于零，该余额就是该供应商可用预付款。

```text
供应商预付款余额 = 有效 payment.remaining_amount 的供应商维度汇总
```

预付款不是 `payment` 以外的新表，也不要求付款单在创建时关联单一采购发票。与收款侧一致，付款单和应付款的多对多分配唯一由 `payment_writeoff` 表达。

### 预付核销流程

```text
供应商预付款
  -> 创建并过账采购发票
  -> 自动生成应付款
  -> 选择预付款和应付款，创建付款核销批次
  -> 写入 payment_writeoff
  -> 同步更新 payment 与 payable 的已核销、未核销金额和状态
```

一笔 `payment` 可以产生多条 `payment_writeoff`，分别核销多笔应付款；一笔 `payable` 可以由多笔付款分次核销。不得在付款单中保存单一采购发票外键表达该关系。

### 核销不变量

每次付款核销在单一事务内完成，对付款单和应付款执行行锁或同等乐观锁控制。必须满足：

```text
payment_writeoff.amount > 0
payment.supplier_id = payable.supplier_id
payment.payment_type = ADVANCE_PAYMENT
payment.remaining_amount >= payment_writeoff.amount
payable.remaining_amount >= payment_writeoff.amount

payment.written_off_amount + payment.remaining_amount = payment.amount
payable.written_off_amount + payable.remaining_amount = payable.amount
```

核销成功后同步更新双方余额和状态。禁止仅插入 `payment_writeoff` 而不更新余额；禁止绕过核销明细直接更新 `written_off_amount` 或 `remaining_amount`。

已核销或部分核销的付款单、应付款和采购发票不能直接冲正。必须先执行受控反核销，删除或失效对应核销关系并恢复双方余额，再按采购发票/付款冲正流程处理，完整保留操作审计。

### 状态和查询口径

| 对象 | 未核销 | 部分核销 | 已核销 |
| --- | --- | --- | --- |
| `payable` | `remaining_amount = amount` | `0 < remaining_amount < amount` | `remaining_amount = 0` |
| `payment` | `remaining_amount = amount`，余额可作为预付款 | `0 < remaining_amount < amount` | `remaining_amount = 0` |

- **供应商应付余额**：有效 `payable.remaining_amount` 按供应商汇总。
- **供应商预付款余额**：有效 `payment.remaining_amount` 按供应商汇总；当前镜像规则下只计 `payment_type=ADVANCE_PAYMENT`。
- **采购发票已付金额**：对应应付款的 `written_off_amount`。
- **采购发票未付金额**：对应应付款的 `remaining_amount`。
- **应付账龄**：按 `payable.due_date` 或应付确认日与查询日的差值计算，以未核销余额为统计金额。

## 数据模型

### 付款主从表

`payment` 以现有 `receipt` 为字段镜像，`payment_detail` 以 `receipt_payment` 为字段镜像。为保证与现有收款 API、PO、Mapper 的表意对称，付款明细沿用 `bank_account_id` 字段名，实际关联 `fund_account.id`；不在本次新功能中改写收款侧历史命名。

| 表 | 关键字段 | 约束 |
| --- | --- | --- |
| `payment` | `payment_no`、`supplier_id`、`payment_date`、`amount`、`written_off_amount`、`remaining_amount`、`payment_type`、`status` | `(corpid, payment_no)` 唯一；按供应商、日期、状态查询 |
| `payment_detail` | `payment_id`、`bank_account_id`、`payment_method`、`amount`、`handling_fee`、`transaction_no` | 按 `(corpid, payment_id, del)` 查询 |
| `payment_writeoff` | `writeoff_no`、`payment_id`、`payable_id`、`writeoff_date`、`amount` | `(corpid, writeoff_no, payment_id, payable_id)` 唯一 |

### 采购发票与应付款表

| 表 | 关键字段 | 约束 |
| --- | --- | --- |
| `purchase_invoice` | `invoice_no`、`supplier_invoice_no`、`supplier_id`、`invoice_date`、`due_date`、金额、状态、审核状态 | `(corpid, invoice_no)` 唯一 |
| `purchase_invoice_line` | `purchase_invoice_id`、`line_no`、商品快照、数量、单价、税率、金额 | `(corpid, purchase_invoice_id, line_no)` 唯一 |
| `purchase_invoice_business_ref` | `purchase_invoice_id`、`ref_type`、`ref_id`、`amount` | 表头归属关系唯一 |
| `purchase_invoice_line_source` | `purchase_invoice_line_id`、来源类型、来源表头/行、数量和金额 | 支持发票行拆分或汇总多个来源 |
| `payable` | `payable_no`、`supplier_id`、`source_type`、`source_invoice_id`、日期、到期日和余额 | 正常采购发票的 `(corpid, source_invoice_id)` 唯一 |

### 统一资金流水

`fund_transaction` 是已生效收付款明细的统一只读流水，不能以 `receipt_payment` 和 `payment_detail` 临时拼接替代。每个有效收付款明细的正常过账最多生成一条流水：

```text
收款明细：direction = IN,  business_type = RECEIPT
付款明细：direction = OUT, business_type = PAYMENT
```

金额以绝对值保存；方向决定收支。`cash_amount` 表示账户实际变动绝对额：收款为 `amount - handling_fee`，付款为 `amount + handling_fee`。冲正通过反方向 `REVERSAL` 流水完成，原流水不得直接修改或删除。

## 后端交付边界

付款、应付款和付款核销属于 `xbb-erp-module-settlement`；采购发票及其对采购订单/采购入库的来源占用属于 `xbb-erp-module-purchase`。跨模块协作应以轻量契约完成：

```text
采购发票过账
  -> PurchaseInvoicePostingService
  -> PayableCommandApi.createFromPurchaseInvoice(...)
  -> PayableService 在同一业务编排内创建或幂等取得 payable
```

付款核销服务应镜像 `ReceiptWriteOffService`，但将领域对象、仓储和错误语义替换为 `Payment`、`Payable`、`PaymentWriteOff`、供应商和预付款。核销批次号使用 `BizNoGenerator` 的独立业务编码，付款核销与预收核销不得共享编号序列。

推荐实施顺序：

1. 新增采购发票主从表、来源表、应付款、付款主从表和付款核销表迁移。
2. 实现采购发票的草稿、审核、过账、作废/红冲及采购订单开票状态同步。
3. 实现应付款创建、列表、余额与账龄查询。

## 验收标准

- 一张已过账采购发票只创建一笔对应应付款；重复过账不会重复创建。
- 采购发票必须存在采购订单行或采购入库行来源；来源数量和金额不能超过来源行的可开票余额。
- 付款单与付款明细金额一致；草稿、校验失败或事务回滚不会写入正式付款、应付款、核销或资金流水。
- 只有预付款能够通过 `payment_writeoff` 核销应付款；付款和应付款必须属于同一供应商，且双方余额均足够。
- 一预付多应付、多预付一应付均正确更新 `written_off_amount`、`remaining_amount` 和核销状态。
- 预付核销不生成重复资金流水；付款明细只在付款正式生效时生成一条 `OUT` 资金流水。
- 采购发票、应付款、付款单和付款核销的列表筛选只能使用服务端字段元数据派生的白名单。
