# 开票业务设计

## 适用范围

本文定义 ERP 销售开票、应收、客户收款与核销的业务模型和规则，适用于销售订单、销售出库、销售发票、应收和收款能力的后续实现。采购发票规则以《资金往来业务设计》中的采购发票章节为准。

本文是开票业务语义与设计方案的事实来源。当前销售订单、销售出库字段以 `docs/features/module-sales/field-design/sales-order.yaml` 和 `docs/features/module-sales/field-design/sales-outbound.yaml` 为准；实际执行数据库结构以 Flyway 迁移为准。

## 目标与边界

### 目标

- 以销售发票作为客户应收的确认来源和客户对账主单据。
- 支持从销售订单、销售出库或合同里程碑生成发票，并保留可追溯的来源关系。
- 支持一笔收款核销多笔应收、一笔应收由多笔收款结清，以及先收款后开票的预收场景。
- 使开票金额、已收金额、未收金额、账龄和逾期情况可准确查询。

### 非目标

- 本期不实现税控平台、电子发票开具、红冲上传等外部税务集成；销售发票是 ERP 内部业务发票。
- 本期不将合同作为销售模块的前置必需单据；合同/项目关联按可选业务归属处理。
- 本期不要求所有发票使用回款计划。仅分期、里程碑或催收预测场景启用计划能力。

## 统一术语

| 术语 | 定义 | 不应混同为 |
| --- | --- | --- |
| 销售发票 | 确认向客户收取货款或服务款的业务单据 | 客户实际来款 |
| 应收开放项 | 一笔待核销的客户债权 | 独立的销售发票副本 |
| 客户收款 | 企业实际收到的客户款项 | 必然已结清的发票款 |
| 预收款 | 尚未分配到应收开放项的客户收款余额 | 另一套收款单据模型 |
| 核销 | 收款余额与应收余额的金额匹配 | 删除、修改或关闭原始单据 |
| 发票业务归属 | 发票与合同、订单、项目的表头级关系 | 发票明细的精确开票来源 |
| 发票明细来源 | 发票行对合同明细、订单行、出库行或里程碑的实际金额/数量占用 | 仅用于查询的表头标签 |
| 合同明细 | 合同中约定的一项具体商品或服务，以及其数量、价格、税率和可开票额度 | 产品 SKU 主数据 |
| 合同外附加项 | 不占用合同明细额度、经授权加入合同发票的发票行 | 删除合同项后重新添加的合同项 |

## 领域关系

```text
销售订单 ──> 销售出库 ──> 销售发票 ──> 应收开放项
     │              │          │              ▲
     └──────────────┴──> 发票明细来源           │
                         │                       │
合同 / 项目 ────────────> 发票业务归属           │
                                                 │
客户收款（含预收） ─────> 核销明细 ──────────────┘
```

销售发票是应收的业务来源；应收开放项是用于余额、账龄和核销的财务对象。二者不是两套由用户分别录入的单据：销售发票审核并过账后，系统自动创建对应应收开放项。

客户收款统一表达实际收到的钱。收款发生时若尚无匹配发票，收款的未核销余额即为预收款；后续创建应收后，仍通过同一种核销明细抵扣，不另建预收核销模型。

## 核心对象与职责

| 对象 | 职责 | 关键余额或金额 |
| --- | --- | --- |
| `sales_invoice` | 销售发票表头，固化客户、日期、税额、总额、账期和状态 | 含税总额 `amount` |
| `sales_invoice_line` | 销售发票行，固化商品/服务、数量、单价、税率与金额快照 | 行含税金额 `amount` |
| `sales_invoice_line_source` | 记录发票行实际占用的订单行、出库行或里程碑 | 本次开票数量、金额 |
| `sales_invoice_business_ref` | 记录发票表头归属的合同、订单、项目等业务对象 | 可选归属金额 |
| `receivable` | 由发票过账生成的应收开放项，也可容纳期初或调整来源 | 初始、已核销、未核销金额 |
| `receipt` | 客户实际收款，统一承载普通收款、预收和期初收款 | 实收、已核销、未核销金额 |
| `receipt_writeoff` | 记录一笔收款对一笔应收的实际核销金额 | 核销金额 |

### 销售发票与应收的关系

正常销售发票遵循一对一规则：一张已过账销售发票最多生成一笔应收开放项；一笔销售应收开放项只对应一张销售发票。

```text
sales_invoice.id = receivable.source_invoice_id
```

期初应收、手工调账等不来源于销售发票的应收开放项，使用 `source_type` 标记来源，`source_invoice_id` 可为空。

### 发票、订单、出库与合同的关系

不在发票或应收表头强制保存单一 `sales_order_id`、`outbound_id`、`contract_id`，避免将真实的多对多业务关系压缩为错误的一对一关系：

```text
一个订单 -> 多次出库 -> 多张发票
一张发票 -> 多个订单 / 多张出库单
一个合同 -> 多个订单、里程碑和发票
```

- 发票行的精确来源由 `sales_invoice_line_source` 表达。
- 发票表头对合同、订单、项目的归属由 `sales_invoice_business_ref` 表达。
- 当前商品贸易场景优先以已审核销售出库明细作为开票来源；服务或未出库场景可使用合同明细或销售订单明细；项目场景可使用合同里程碑。
- 手工开票允许没有来源关系，但必须记录手工来源类型并接受权限与审核控制。

## 业务流程

### 从出库开票并收款

```text
审核销售订单
  -> 审核销售出库
  -> 选择可开票出库明细，生成销售发票草稿
  -> 审核/过账销售发票
  -> 自动生成应收开放项
  -> 新建客户收款
  -> 收款核销应收
```

### 先收款后开票（预收）

```text
客户付款
  -> 新建客户收款，未核销余额为预收余额
  -> 后续生成并过账销售发票
  -> 自动生成应收开放项
  -> 用原收款核销该应收
```

例如客户先付款 10,000 元，后续销售发票金额为 12,000 元。核销后，收款已核销 10,000 元，发票对应应收剩余 2,000 元；该余额继续等待后续收款。

### 一收多销与多收一销

- 一笔 `receipt` 可建立多条 `receipt_writeoff`，分别核销多笔应收。
- 一笔 `receivable` 可被多条 `receipt_writeoff` 分次核销。
- 不通过在 `receipt` 中保存单一发票外键表达上述关系；核销明细是唯一正式的资金分配依据。

## 状态与余额规则

### 销售发票状态

| 状态 | 含义 | 允许的关键动作 |
| --- | --- | --- |
| 草稿 | 可编辑，尚未确认应收 | 编辑、删除、提交审核 |
| 已审核 | 业务审核通过，等待或执行过账 | 过账、在未发生下游业务时反审核 |
| 已过账 | 金额确认，已生成应收开放项 | 查询、收款核销、按规则开贷项发票 |
| 已作废 | 未生效或已被合法冲销 | 仅查询追溯 |

销售发票一旦过账，不允许直接修改客户、金额、税率、来源占用和到期日。需要减少或撤销金额时，以贷项发票或红冲业务处理，并同步生成冲减应收的开放项或核销记录；不得物理删除历史单据。

### 收款与应收状态

| 对象 | 未核销 | 部分核销 | 已核销 |
| --- | --- | --- | --- |
| `receivable` | `remaining_amount = amount` | `0 < remaining_amount < amount` | `remaining_amount = 0` |
| `receipt` | `remaining_amount = amount`，在未有发票时即为预收余额 | `0 < remaining_amount < amount` | `remaining_amount = 0` |

每次核销在一个事务内完成，并锁定关联收款和应收记录，保证以下不变量：

```text
writeoff.amount > 0
receipt.customer_id = receivable.customer_id
receipt.remaining_amount >= writeoff.amount
receivable.remaining_amount >= writeoff.amount

receipt.written_off_amount + receipt.remaining_amount = receipt.amount
receivable.written_off_amount + receivable.remaining_amount = receivable.amount
```

核销成功后同步更新双方的已核销金额、剩余金额和状态。禁止仅插入核销明细而不同步余额，也禁止绕过核销明细直接修改余额。

## 开票生成与来源占用规则

### 基于合同开票

基于合同创建发票时，用户在“添加合同项”中选择的是**合同明细行**，而不是仅选择产品 SKU。产品 SKU 用于标识产品是什么；合同明细用于确定本合同中约定了哪一项、可开数量/金额是多少，以及应采用的合同价格和税率。

```text
产品 SKU：A 产品是什么
合同明细：合同 C 中 A 产品的某一条约定
发票明细：本次实际针对该合同明细开多少
发票明细来源：记录本次占用的合同明细及数量/金额
```

例如同一合同有两条 SKU 均为 A 的合同明细：

```text
合同明细 101：A 产品，100 件，单价 100，普通交付
合同明细 102：A 产品，50 件，单价 90，特殊批次
```

二者必须按 `contract_item_id` 分别选择和占用，不能仅根据 `sku_id` 自动合并。发票行及其来源关系应保留具体的合同明细标识：

```text
sales_invoice_line：A 产品，60 件
sales_invoice_line_source：
  source_type = CONTRACT_LINE
  source_id = contract.id
  source_line_id = contract_item.id
  quantity = 60
  amount = 本次开票金额
```

合同项选择列表至少显示合同明细行号、SKU/名称/规格、合同数量/金额、合同单价、税率、已开票数量/金额、可开票数量/金额及业务备注，避免同 SKU 多行时误选来源。

#### 合同项的部分开票与再次开票

发票草稿默认可带入可开票的合同明细，但用户删除发票中的某个合同项，仅表示该项**不参与本次发票**，不会删除或关闭合同明细。

本次发票过账后，系统按有效来源关系累计占用；下一次基于同一合同开票时，应展示仍有可开票余额的合同明细，而不是简单展示全部合同产品或过滤所有曾被开过的产品：

```text
合同明细可开票数量 = 合同明细约定数量 - 有效发票累计占用数量
合同明细可开票金额 = 合同明细约定金额 - 有效发票累计占用金额
```

例如合同明细 A 产品为 100 件，本次发票最终以该合同明细为来源开出 60 件并过账，则下次应显示该合同明细仍可开 40 件。草稿和已作废发票默认不占用最终可开票额度；审核中单据是否临时占用由实现统一定义，默认建议占用以避免并发重复开票。

若用户先删除带入的 A 产品行，再重新选择 A 产品，只有从“添加合同项”重新选择原 `contract_item_id` 的行为才会继续占用该合同明细额度。若仅从 SKU 选择器手工新增同 SKU 产品而未关联合同明细，系统不能推断其应占用哪一行合同项，且会导致下次仍显示原合同额度，存在重复开票风险。

#### 合同外附加项

“添加附加项”是与“添加合同项”分离的入口：前者从产品 SKU 主数据选择商品或服务，后者从合同明细选择约定项。

```text
添加合同项：contract_item -> 发票行 -> CONTRACT_LINE 来源关系
添加附加项：SKU -> 发票行 -> MANUAL / CONTRACT_EXTRA 来源关系
```

合同外附加项不关联 `contract_item_id`、不占用合同明细的可开票额度，必须记录附加原因并受权限或审批控制。默认禁止使用合同外附加项添加一个已存在于合同中的同 SKU 产品，以规避合同明细额度控制；如确有合同变更，应优先补充或变更合同明细后再开票。

### 可开票数量与金额

从订单行或出库行生成发票时，系统按来源行计算可开票余额：

```text
可开票数量 = 来源确认数量 - 已有效开票占用数量
可开票金额 = 来源确认金额 - 已有效开票占用金额
```

- 从出库开票时，来源确认数量为已审核出库数量。
- 从订单开票时，来源确认数量或金额以经过审核且允许直接开票的订单约定为准。
- 合同里程碑开票按已达成的里程碑金额控制。
- 草稿或已作废发票不占用最终可开票额度；已过账发票占用额度。审核中是否占用由实现统一定义，默认建议占用以避免重复提交。

### 金额一致性

必须校验：

```text
销售发票表头未税金额 = 有效发票明细未税金额之和
销售发票表头税额 = 有效发票明细税额之和
销售发票表头含税金额 = 有效发票明细含税金额之和

有来源的发票明细金额 = 其有效来源占用金额之和
```

金额计算、税额舍入与尾差处理应使用统一的金额服务；不得由前端提交的表头合计直接作为可信结果。

## 数据设计约束

### 发票相关表

| 表 | 关键字段 | 关键约束 |
| --- | --- | --- |
| `sales_invoice` | `invoice_no`、`customer_id`、`invoice_date`、`due_date`、`amount`、`status` | `(corpid, invoice_no)` 唯一 |
| `sales_invoice_line` | `sales_invoice_id`、`line_no`、商品/服务快照、数量、单价、税率、金额 | `(corpid, sales_invoice_id, line_no)` 唯一 |
| `sales_invoice_line_source` | `sales_invoice_line_id`、`source_type`、`source_id`、`source_line_id`、占用数量/金额 | 支持一行发票拆分或汇总多个来源 |
| `sales_invoice_business_ref` | `sales_invoice_id`、`ref_type`、`ref_id`、归属金额 | `(corpid, sales_invoice_id, ref_type, ref_id)` 唯一 |

### 应收与收款相关表

| 表 | 关键字段 | 关键约束 |
| --- | --- | --- |
| `receivable` | `source_type`、`source_invoice_id`、客户、金额、已核销、余额、到期日 | 正常销售发票在 `(corpid, source_invoice_id)` 上唯一 |
| `receipt` | 客户、收款日期、实收金额、已核销、余额、收款方式 | 不强制关联订单、出库或发票 |
| `receipt_writeoff` | `receipt_id`、`receivable_id`、核销日期、金额 | 仅允许同客户、同租户的有效开放项互相核销 |

### 可选回款计划

当一张发票需要按期次、验收、质保或合同节点收款时，在 `receivable` 下新增 `receivable_plan`。计划总金额必须等于应收初始金额；核销明细可选关联计划行，以支持逾期催收和现金流预测。

未启用回款计划时，发票 `due_date` 与应收 `due_date` 即为单一到期日，不应为了预留功能强制创建计划记录。

## 关键校验与异常场景

| 场景 | 处理规则 |
| --- | --- |
| 发票客户与上游来源客户不一致 | 禁止生成或提交发票 |
| 发票金额超过可开票余额 | 禁止提交，并提示来源单据剩余可开票数量/金额 |
| 已过账发票需要改价或减少金额 | 不直接修改；通过贷项发票/红冲处理 |
| 收款客户与应收客户不一致 | 禁止核销 |
| 收款或应收余额不足 | 禁止超额核销；并发核销使用行锁或乐观锁控制 |
| 收款金额大于当前应收 | 允许收款存在余额；余额作为预收继续保留 |
| 预收款需要指定业务用途 | 可增加收款业务归属关系记录；不替代正式核销 |
| 已核销单据需要撤销核销 | 先生成反核销记录或执行受控反核销，再恢复双方余额；保留审计轨迹 |
| 销售订单反审核 | 已生成有效出库、发票、收款业务归属或其他下游单据时禁止反审核，具体下游范围以销售模块规则为准 |

## 查询与报表口径

- **客户应收余额**：有效 `receivable.remaining_amount` 按客户汇总。
- **客户预收余额**：有效 `receipt.remaining_amount` 按客户汇总；不要求 `receipt_type = ADVANCE_PAYMENT`，因为普通收款未分配时同样属于可用预收余额。
- **发票已收金额**：对应应收的 `written_off_amount`。
- **发票未收金额**：对应应收的 `remaining_amount`。
- **应收账龄**：按 `receivable.due_date` 或应收确认日与查询日的差值计算，以未核销余额为统计金额。
- **开票进度**：来源行已有效开票占用金额/数量与来源确认金额/数量的比较结果。

## 实施边界与后续接口

本设计落地时应新增或扩展以下能力：

1. 销售发票草稿创建、编辑、审核、过账、作废/贷项处理。
2. 从可开票订单行、出库行或里程碑选择并生成发票明细。
3. 发票过账时在同一事务内创建应收开放项并固化来源占用。
4. 客户收款登记、收款余额查询、收款与应收的批量核销及反核销。
5. 客户应收余额、预收余额、发票收款状态、账龄和开票进度查询。
