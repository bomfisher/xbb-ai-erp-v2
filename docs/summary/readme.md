## 经验总结
- ai生成中大型项目首先完成以下事情
  - 确定技术框架，写到rule
  - 确定后端项目结构，至少是核心项目结构
    - 底层的 config、common、log等
    - 顶层的启动包
    - 中间业务包留1到2个用来做验证
  - 一个合适的持久层生成工具，用于快速生成基础controller到mapper
  - ai生成前端项目框架
- 把当前每个包的职责写到rule
- 开始搭建公共底层
  - 优先完成菜单
  - 对接列表
    - 列表页的列表数据、列表表头、筛选项、头部按钮、底部按钮、分页逻辑需要先定义好规范，再去接入前端。
      - 不然会出现扩展困难，不同模块实现方式不同等问题
  - 对接新建页、编辑页
    - 如果未来想要开放字段能力设置的，新建、编辑页的字段维护建议和列表表头方案一并考虑
  


## 零散经验
- 逆向工程很重要
  - 省token
  - 节约时间
  - 提高AI效率
- 做具体的功能时，可以直接在项目中，手动写一下部分实现代码，或者是方法占位，可以帮助AI理解
- 早期业务只做CRUD，等模块完整，在做模块之间或与基础能力之间的对接
- 

## 禁止项
- 早期不要把完整的业务模块设计文档喂给ai，除非是非常小，没有周边耦合的业务
  - 这个时候项目要啥没啥，不足以支持一个业务模块
