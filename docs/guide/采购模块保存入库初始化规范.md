# 采购模块保存入库初始化规范

## 目的

采购初始化 SQL 对部分列声明了 `NOT NULL`，而新建、编辑页面不会暴露所有数据库字段。采购保存接口使用显式列插入时，数据库列默认值不会覆盖 Java 对象中的 `null`，因此新增保存必须在进入 Repository 前完成初始化。

## 适用范围

- `PurchaseRequestSaveAppServiceImpl`：采购申请主档、明细聚合保存。
- `PurchaseOrderSaveAppServiceImpl`：采购订单主档、明细聚合保存。
- `PurchaseRequestItemAdminAppServiceImpl`、`PurchaseOrderItemAdminAppServiceImpl`：明细独立保存。
- `PurchasePendingTaskAdminAppServiceImpl`：待采购任务保存。
- `PurchaseSourceRelationAdminAppServiceImpl`：采购来源关系保存。

仅对新增分支初始化。编辑分支不得因为请求缺少字段而覆盖已有值；明细聚合保存中，新增行按请求顺序生成 `lineNo`。

## 统一规则

1. 只在值为 `null` 或空白字符串时初始化，前端或上游服务显式传值优先。
2. `version=0`、逻辑删除标记 `deleted=0`、数量与金额字段使用 `0`，审计时间使用当前毫秒时间戳。
3. `creatorId`、`modifyId` 优先使用保存请求的 `userId`；页面未暴露的状态、快照和引用字段由后端暂时补齐。
4. `corpid` 是租户边界字段，必须来自请求上下文，不使用跨租户共享的伪造默认值。
5. 该初始化发生在 Repository `insert` 之前，不能依赖 MyBatis 或数据库默认值。

## 当前默认值

| 实体 | 字段 | 空值默认值 | 说明 |
| --- | --- | --- | --- |
| 采购申请主档 | `purchaseOrgId` | `0` | 页面未传时的临时引用占位 |
| 采购申请主档 | `requestNo` | `MOCK-PR-{当前时间}` | 避免单号为空及唯一键冲突 |
| 采购申请主档 | `sourceType` | `manual` | 手工来源占位 |
| 采购申请主档 | `bizStatus` / `approvalStatus` | `1` / `pending` | 初始业务、审批状态 |
| 采购订单主档 | `purchaseOrgId` / `vendorId` | `0` / `0` | 临时引用占位 |
| 采购订单主档 | `orderNo` | `MOCK-PO-{当前时间}` | 避免订单号为空及唯一键冲突 |
| 采购订单主档 | `vendorNameSnapshot` / `currencyCode` | `MOCK` / `CNY` | 页面未传快照、币种占位 |
| 采购订单主档 | `bizStatus` | `1` | 与现有采购状态约定兼容 |
| 采购订单主档 | 其余状态字段 | `pending` | 审批、执行、收料、入库、应付、收票、付款 |
| 采购申请/订单明细 | `skuId` / `purchaseUnitId` | `0` / `0` | 产品选择回写尚未覆盖时的临时引用占位 |
| 采购申请/订单明细 | SKU 编码、名称快照 | `MOCK` | 产品选择回写尚未覆盖时的临时快照 |
| 采购申请/订单明细 | 数量、价格、税率、金额及执行摘要 | `0` | 数据库非空数值列的初始值 |
| 待采购任务 | `purchaseOrgId` / `skuId` | `0` / `0` | 临时引用占位 |
| 待采购任务 | `taskNo` / `sourceType` / SKU 快照 | `MOCK-TASK-{当前时间}` / `manual` / `MOCK` | 页面未覆盖字段占位 |
| 待采购任务 | `taskStatus` | `pending` | 初始任务状态 |
| 采购来源关系 | 来源/目标单据类型 | `MOCK` | 尚未建立来源链路时占位 |
| 采购来源关系 | 来源/目标单据 ID | `0` | 临时引用占位 |
| 采购来源关系 | `relationStatus` | `pending` | 初始关系状态 |

审计字段统一补齐 `version`、`deleted`、`addTime`、`updateTime`、`creatorId`、`modifyId`。`corpid` 和真实业务引用字段一旦由页面或上游服务传入，必须保留原值。

当保存请求没有提供 `userId` 时，审计人临时使用 `MOCK_USER`；正式接口仍应按契约传入真实操作人。

## 明确的临时占位字段

当前仍属于后端 Mock 的字段为：采购组织 ID、供应商 ID、SKU ID、采购单位 ID、供应商及 SKU 快照、采购/任务单号（未传时）、来源关系两端单据类型与 ID，以及订单状态链路和待采购任务/来源关系初始状态。产品选择接口已有的 `purchaseUnitId=1`、数量、仓库、价格和税率占位规则，继续以对应产品业务选择接口文档为准。

## 维护要求

- 新增采购表或修改 DDL `NOT NULL` 列时，必须同步检查保存入口、Assembler、默认初始化组件和本规范。
- 每个新增保存入口至少包含“空值补齐”和“显式值保留”测试。
- 页面字段逐步补齐后，应删除对应 Mock 默认值，并同步更新本表和 API 文档。
