# 工程规则唯一事实源

## 适用与优先级

本文件是本仓库业务开发的唯一工程规则源。发生冲突时，按“用户明确要求 → 根 `AGENTS.md` 的工作方式 → 本文件 → 模块局部约束 → 既有代码”的顺序处理；规则本身需要调整时，先修改本文件，再修改引用它的 SKILL。

## 分层与依赖

- 项目采用 DDD：`admin -> application -> domain`，`infrastructure` 实现领域或应用端口；Domain 不依赖 HTTP、ORM、PO、DTO、VO。
- Controller 只处理 HTTP 边界和结果包装，禁止直接调用 Mapper；持久化必须通过 Repository。
- 多主子档保存由应用服务编排并设置事务边界；列表子档摘要必须批量查询，禁止循环查库。

## 对象与接口

- HTTP 入参使用 `*DTO`，非脚本接口 DTO 继承 `BaseDTO`；HTTP 出参使用 `*VO`；内部中转使用 `*Pojo`。
- 数据库映射对象使用 `*PO` 后缀，数据库布尔含义使用 `Integer`，不用 `Boolean`；枚举使用 `*Enum`。
- 所有 `infrastructure.persistence.po` 下的 `*PO` 必须继承 `xbb.ai.erp.base.persistence.entity.BaseEntity`，不得重复声明 `id`、`del/deleted`、`addTime`、`updateTime` 基础字段。
- 成功响应使用 `ResultVO.success()`；无业务返回值使用 `BaseVO`；员工标识 `userId` 为字符串。
- 主动参数、协议和业务失败使用 `BizException`，不得静默吞错或以 `null` 表达失败。

## 安全与配置

- 禁止把数据库、Redis、Token、密钥等真实凭据提交到仓库；应用配置只引用环境变量，示例值放 `.env.example`。
- 数据库结构变更必须遵循 `数据库迁移规范.md`，不能只新增 `docs/sql` 文件。
- 不得通过前端输入直接传递数据库列名、排序 SQL 或过滤操作符；必须有服务端白名单映射。

## Agent 行为

- 开始前阅读本文件、目标模块、相关 API 文档与 `docs/guide/DDD业务模块开发指南.md`。
- 修改前检查 `git status --short`，保护现有变更；是否创建工作树由用户明确决定。
- 接口变化必须执行文档编排；交付前运行 Harness 校验和相关测试，并如实报告未验证项。
